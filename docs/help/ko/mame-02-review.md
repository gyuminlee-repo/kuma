# 단계 2. 분석 및 검토

시퀀싱 결과를 웰마다 판정하고 96-well 플레이트 위에서 확인한다. 2.1 에서 입력을 고르고 2.2 에서 판정을 읽는다.

## 2.1 입력

| 입력 | 필수 |
|---|---|
| MinKNOW 실행 폴더 | 필수 |
| 기대 변이 목록 (xlsx) | 필수 |
| 참조 construct | 필수 |
| 사용할 웰 | 선택. 손대지 않으면 앞쪽 웰을 쓴다 |

입력을 고른 뒤 **실행** 또는 **유효성 검사** 를 누른다. Cell stock 제작은 이 화면에 없고 step 3 에서 다룬다.

### run 폴더에서 읽는 파일

MinKNOW 가 만든 폴더를 그대로 넣는다. read 를 barcode 폴더별로 미리 나눠 둘 필요가 없다.

| 파일 | 쓰임 | 필수 |
|---|---|---|
| `fastq_pass/` 아래 barcode 폴더의 `*.fastq` 또는 `*.fastq.gz` | 분석에 쓰는 read | 필수 |
| `final_summary_*.txt`, `sample_sheet_*.csv` | run 이름과 시료 정보 | 있으면 읽음 |
| `sequencing_summary*.txt` 또는 `*.tsv` | read 품질과 barcode 교차오염 점검 | 있으면 읽음 |
| `pore_activity_*.csv`, `throughput_*.csv`, `barcode_alignment*.tsv` | run 건강 지표 | 있으면 읽음 |
| `report_*.json` | flow cell 종류와 공극 수 | 있으면 읽음 |

압축 여부는 상관없다. `*.fastq` 와 `*.fastq.gz` 를 모두 읽는다.

`report_*.json` 은 run 폴더에 없으면 한 단계 위 폴더에서 찾는다. 끝내 없으면 공극 값이 빈칸으로 남는다. 빈칸은 0 이 아니다.

`pod5/`, `fast5/`, `bam_pass/`, `other_reports/`, `report_*.html` 은 읽지 않는다. 지우지 않아도 되고 넣어도 달라지지 않는다.

### 사용할 웰

"사용할 웰" 패널은 계산된 배치를 플레이트 위에 그린다. 각 변이는 플레이트 순서(A1, B1, ... H1, A2)가 정해준 웰에 고정되며 웰을 눌러도 자리가 움직이지 않는다. 선택은 이 캠페인이 실제로 채운 웰이 어디인지만 말한다.

선택하지 않은 웰은 캠페인이 채우지 않은 웰이므로 판정하지 않는다. 그 웰에 배치돼 있던 샘플은 2.2 에서 이름으로 표시된다. 샘플 수보다 적게 고르는 것은 일부 웰만 채운 플레이트라는 뜻일 뿐 거부 사유가 아니다. 거부되는 유일한 선택은 아무 웰도 고르지 않은 빈 선택이다.

같은 패널의 **바코드 작업목록 (csv)** 버튼은 채운 웰마다 웰, 샘플, 바코드 토큰, 시드 프라이머 이름을 한 행씩 적은 파일을 저장한다. 벤치에서 분주할 때 쓴다.

### 고급 옵션

파라미터 패널의 **고급 옵션** 에 네 가지가 있다.

| 화면 표기 | 기본값 | 무엇이 달라지는가 |
|---|---|---|
| Coverage Fraction | 0.98 | read 하나가 reference 를 얼마나 덮어야 통과하는지 정한다. 올리면 온전한 정렬만 남고 내리면 부분 정렬도 들어온다 |
| 최소 매핑 품질(0–60) | 25 | 이 값보다 매핑 품질이 낮은 read 를 버린다 |
| Edit Distance Ratio | 0.25 | barcode 를 얼마나 느슨하게 맞출지 정한다. 작을수록 엄격해져 배정되는 read 가 줄어든다 |
| Chimera Split | 켬 | 한 read 가 여러 well 에 걸친 경우를 나눠서 센다. 켜 둔다 |

나머지 판정 기준값은 화면에서 바꿀 수 없다.

### 입력을 바꾸면 이전 결과가 지워진다

실행 폴더, 기대 변이 목록, 참조 construct, 선택한 웰, 분석 파라미터 중 하나라도 바꾸면 이전 실행이 만든 판정과 플레이트 맵이 사라지고 2.2 는 실행 전 상태로 돌아간다. 끝난 실행의 화면이 새 입력의 결과처럼 보이는 것을 막는 동작이다. 같은 값을 다시 고르면 아무 일도 일어나지 않는다. 출력 경로는 입력이 아니므로 결과를 지우지 않는다.

### 실행이 거치는 단계

아래는 MinKNOW 실행 폴더를 넣었을 때의 경로다. 이미 만들어 둔 FASTA 폴더를 넣는 나머지 두 모드는 앞쪽 단계를 건너뛴다. 2 번부터는 진행 막대에 아래 이름 그대로 뜬다.

1. **Amplicon 잘라내기.** barcode 워크북의 프라이머가 reference 어디에 붙는지 찾아 그 사이 구간만 잘라 정렬용 reference 로 쓴다. 찾지 못하면 준 reference 를 그대로 쓴다.
2. **정렬 중.** 앱에 포함된 minimap2 가 `fastq_pass` 의 read 를 reference 에 붙인다.
3. **커버리지 필터.** 매핑 품질이 낮은 read 와 reference 를 충분히 덮지 못한 read 를 버린다.
4. **역다중화 중.** 남은 read 의 양끝 barcode 를 읽어 96 well 중 하나에 배정한다. 어느 한쪽 barcode 를 정하지 못하거나 동점이면 그 read 를 버린다.
5. **컨센서스 생성 중.** well 마다 같은 자리의 염기를 모아 다수결로 서열 하나를 만든다. 품질이 낮은 염기는 투표에서 빼고 read 가 너무 얕은 자리는 `N` 으로 둔다.
6. **분석 중.** well 별 서열을 기대 변이와 대조해 판정을 매긴다.

### 실행이 남기는 파일

- 웰별 consensus 서열. 출력 폴더의 barcode 폴더(`sort_barcodeNN/`) 아래에 `{R}_{F}.fasta` 로 쌓인다.
- 전체 웰을 합친 `final/consensus_all_dna.fasta`.
- 화면의 판정표와 plate 그림.
- 선정 클론 목록 `..._picks.csv`.
- Excel 워크북. 실행에 지정한 출력 경로에 쓴다.

run 마다 출력 폴더를 따로 쓴다. 이전 run 이 남긴 plate 폴더는 판정에서 빼고 화면에 이름을 알려 준다.

## 2.2 판정 검토

왼쪽에 판정표, 오른쪽에 96-well 플레이트 맵과 플레이트별 판정 막대 그래프가 있다. 판정표 위의 탭은 Final, ALL, 그리고 이번 실행에 실제로 있는 native barcode 다. Final 은 변이마다 선정된 replicate 의 웰만 남긴다.

### 판정표 위에 뜨는 안내

안내는 방금 끝난 실행을 두고 조건에 해당할 때만 뜬다. 여러 개가 함께 뜰 수 있고 알릴 것이 없으면 아무것도 뜨지 않는다. 이전 실행의 안내는 쌓이지 않는다. 입력을 바꾸면 이전 결과와 함께 사라지고 다시 실행하면 새 결과로 다시 정해진다.

- **이 런은 판정할 수 없다** 웰당 read 중앙값이 하한에 못 미친다. 아래 판정은 읽을 깊이가 없던 플레이트의 산물이므로 그대로 쓰지 말고 시퀀싱을 다시 한다.
- **판정은 가능하지만 깊이가 부족한 런이다** 하한은 넘고 권장치에 못 미친다. 판정을 쓰되 경계에 있는 웰은 따로 확인한다. 깊이는 이번 런이 실제로 판정한 웰에서만 잰다.
- **레퍼런스 끝에 있는 변이** 기대 변이의 코돈이 레퍼런스 끝 가까이 있으면 그 변이 이름을 적어 준다. 정렬기가 그 자리에서 read 를 잘라내므로 웰이 보고하는 깊이보다 얕게 읽힐 수 있다. 프라이머가 붙는 구간까지 포함한 레퍼런스로 다시 실행한다.
- **샘플 N개는 이번 플레이트에 없다** 선택에서 빠진 웰에 배치돼 있던 샘플의 이름과 웰을 알려 준다. 이번 런에 판정이 없는 것이 정상이며 그 샘플이 필요하면 다음 런에 넣는다.
- **well-변이 대응 오류 의심** 웰마다 관측 변이가 자기 기대 변이보다 다른 웰의 기대 변이와 더 잘 맞는 상태다. 실행을 막지는 않으니 결과를 쓰기 전에 플레이트 분주와 샘플 이름의 대응을 확인한다. 관측 변이가 있는 웰이 24개 미만이면 표본이 작아 판정하지 않는다.

같은 자리에 플로우셀 id 와 공극 수도 나온다. 참고용이며 합격선으로 쓰지 않는다.

### 판정 근거 열기

- **복제본 행**: 판정 상세의 replicate 목록은 버튼이다. 행을 누르면 그 플레이트 복제본이 선택되고 상세, 플레이트 강조, 판정표가 함께 따라 움직인다.
- **confidence 지표**: 지표 이름을 누르면 무엇을 센 값인지, 파이프라인 어느 단계에서 센 값인지, 판정을 움직이는 값인지가 나온다. 이번 실행이 대조한 임계값도 함께 적는다. 열 개 지표 중 일곱 개는 진단용이라 판정을 바꾸지 않는다.
- **판정 범례**: 플레이트 맵 범례와 판정 막대 그래프에서 클래스 위에 마우스 커서를 올리면 그 클래스의 뜻이 나온다. 웰이 하나도 없는 클래스도 마찬가지다.

## 판정 클래스

<!-- guide-verdict-order -->

웰 하나의 판정은 정해진 순서로 조건을 확인해 처음 맞는 조건에서 정해진다. 깊이(Low depth)와 reading frame(Frameshift)을 먼저 본다. 기대 변이가 모두 맞는데 indel 신호가 임계값 이상이면 여기서 Ambiguous 가 된다. 그다음 No call, Many, Mixed, Wrong AA 를 차례로 확인한다. 기대 변이가 모두 맞은 웰만 마지막에 Ambiguous 또는 Pass 가 된다. Ambiguous 는 기대 위치 근처에 추가 변화가 있을 때다.

| 판정 | 의미 |
|---|---|
| Pass | 관측된 아미노산 변화가 설계와 정확히 일치한다 |
| Ambiguous | 기대 변이는 모두 일치한다. 여기에 기대 위치의 indel window 안에서 아미노산 변화가 하나 더 관측됐거나 read 의 indel 이벤트 신호가 임계값 이상이다(WT 대조군에도 붙을 수 있다). 검출로 계산한다 |
| Mixed | well 내 오염이다. consensus 신호에 두 번째 대립유전자가 상당량 섞여 있다 |
| Wrong AA | 기대 위치의 아미노산이 다르거나 기대한 변이가 없다. 또는 window 안에는 추가 변화가 없고 window 밖에만 예상치 못한 변화가 있다 |
| Frameshift | consensus 의 순 삽입 또는 결실 길이가 3 의 배수가 아니어서 reading frame 이 어긋났다 |
| Many | 관측된 아미노산 변화 수가 설계 개수와 다중 변이 상한을 모두 넘었다 |
| Low depth | 이 well 을 신뢰성 있게 판정하기에는 read 가 너무 적다 |
| No call | consensus 에 모호한 (N) 위치가 너무 많아 아미노산 판정을 신뢰할 수 없다 |

판정이 하나도 안 나오거나 커버리지 필터에서 read 가 많이 버려지는 등 자주 겪는 문제는 [자주 묻는 질문](faq.md) 에 정리돼 있다.
